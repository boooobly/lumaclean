# Решения владельца после аудита — 01.11.2026

Источник: ответ владельца в этом чате: «Для духовки 45 минут сделай, а касательно цены, пусть скачек остается».

1. Стандартная духовка: 45 человеко-минут на одну единицу (вопрос владельцу был именно о человеко-минутах). Цена 1400 RSD сохраняется. В `src/lib/appliance-catalog.ts` — `ovenWorkMinutes=45`; CRM использует её как предложение для нового правила/новой версии. Количество духовок умножается на 45; число клинеров само по себе эту величину не делит. Параллельное распределение всей уборки и базовые длительности ещё требуют подтверждения.
2. Граница 100 м²: сохранить текущие numeric bands и скачок. Deep: 99.99 → 17000, 100 → 18000, 100.01 → 18100 RSD. Move: 99.99 → 18400, 100 → 18000, 100.01 → 18100 RSD. Итог округляется вверх до 100 один раз; сглаживания ставок нет.

Live Google Sheets и production DurationRule не редактировались. При отдельном обновлении источника заменить труд/комментарий духовки на 45 и удалить обещание «скачка нет», сохранив числовые тарифы. Для DB — новая версия через существующий finance command, проверка exact environment/backup, без пересчёта исторических заказов. Это решение не включает AI AUTO и не разрешает production deploy.

LC-10 закрыт как бизнес-блокер, остаётся P2 синхронизации текста источника. LC-07 разрешён только в части духовки; остальные duration gates открыты.

Проверки после решения: unit 1055 PASS / 0 FAIL / 33 SKIP, client SSR 16/16 (поле духовки 45 и отсутствие auto activation), TypeScript, ESLint (два прежних img warnings) и production build PASS. Изолированные DB/HTTP, браузерные и Lighthouse результаты основного аудита сохранены как исторические для этого follow-up; внешний транспорт и production не проверялись повторными записями.
