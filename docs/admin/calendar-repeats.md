# Копирование и ограниченные серии уборок

Выберите карточку в календаре: Ctrl+C, затем день и Ctrl+V. Системный буфер обмена не используется; выделенный текст, поля ввода и мобильные устройства не перехватываются. Также доступны контекстные меню заказа/дня и кнопки. На телефоне откройте заказ и нажмите «Повторить уборку / Сделать регулярной».

Просмотр автоматически загружает дату, время, команду, площадь, extras, длительность и цены. Согласованная цена сохраняется; текущий прайс применяется только явным выбором. Изменения формы требуют нового просмотра. Все заказы создаются в DRAFT, без клиентских уведомлений, старых финансовых операций, фактической длительности, назначений lifecycle, маршрутов, incident notes и AI confirmations. Новые extra/финансовые snapshots самостоятельны.

Серия еженедельная, по выбранным дням. По умолчанию 8 недель; максимум 26 недель и 64 даты. Все времена — Europe/Belgrade, каждое вхождение преобразуется из локального wall time отдельно. Неоднозначные/несуществующие часы DST отклоняются. Если первая дата совпадает с исходным заказом, исходный сохраняется и не дублируется.

Проверки использует существующий assessScheduling: интервалы, резерв, каждый клинер, рабочие часы, транспорт и маршруты. При любых неразрешённых предупреждениях/конфликтах новые копии не создаются; времени автоматически не меняются. Команда и подтверждённая длительность должны быть заданы. Перед записью проверки повторяются под блокировкой клинеров. Batch проверяется также внутри себя, сохраняется атомарно. requestId + hash и транзакционная блокировка защищают double-submit. Повторное отдельное создание на ту же дату требует подтверждения возможного дубля и всё равно не может обойти конфликт.

Карточка участника содержит «Будущие уборки серии». Изменения времени, цены, команды и комментария требуют preview всех будущих дат; остановка отменяет только будущие DRAFT/SCHEDULED. Количество, ревизия серии и digest участников повторно проверяются перед изменением. Одна уборка меняется/отменяется обычными действиями карточки; серия от этого не редактируется. Начатые уборки требуют отдельной обработки. Исходный шаблон хранится в OrderRepeatSeries, связь — copiedFromId/repeatSeriesId; действия пишутся в AuditLog.
