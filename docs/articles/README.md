## Как добавить статью

1. Скопируйте один из файлов материалов в `src/lib/articles/`, задайте новый `id` и оставьте `status: "draft"`.
2. Заполните `translations.ru`, `.sr`, `.en`: уникальные `slug`, `title`, `description`, `lead`, `imageAlt` и `sections`. У каждого раздела должен быть уникальный `id`; он используется в оглавлении. `paragraphs` — обычный текст, `bullets` — список, `tip` — выделенный совет. HTML и отдельная CMS не нужны.
3. Добавьте оптимизированную обложку в `public/media/articles/` и укажите путь в `image`. Выберите подходящие `services`: `regular`, `deep`, `move`, `airbnb`, `office`.
4. Импортируйте материал в `src/lib/articles/index.ts` и добавьте в массив `articles`. Порядок массива задаёт порядок карточек; первый материал — крупная карточка.
5. Укажите фактическую дату правки `updatedAt` в формате `YYYY-MM-DD`. Проверьте текст и переводы в превью.

Пишите о конкретной задаче читателя. Не повторяйте ключевые слова ради SEO, не добавляйте вымышленные отзывы и гарантии. Условия сверяйте с `src/lib/content.ts` и `src/lib/seo-services.ts`, цены — с `src/lib/pricing.ts`. Пример цены в `cost.ts` вычисляется из действующих тарифов; при изменении тарифов обновите дату материала и пересоберите сайт.

## Превью и защита черновиков

Для обычной разработки достаточно `npm run dev -- --hostname 127.0.0.1 --port 3100`.

Для проверки собранного локального превью в PowerShell:

```powershell
$env:ARTICLES_PREVIEW='1'
npm run build
npm run start -- --hostname 127.0.0.1 --port 3100
```

Переменная нужна и при сборке, и при запуске. Локальный сервер привязан к loopback; он не является публичной ссылкой.

- Обычная production-сборка показывает только `published`. `VERCEL_ENV=production` запрещает черновики даже при `ARTICLES_PREVIEW=1`.
- На Vercel Preview черновики разрешены; если понадобится удалённое превью, сначала проверьте Deployment Protection. `noindex` запрещает индексацию, но не заменяет контроль доступа.
- В превью стоят `noindex` в metadata и `X-Robots-Tag: noindex, nofollow` в собранном варианте. Публичные canonical/hreflang появляются только в опубликованной версии; переключатель языка работает и в превью.
- Черновики отсутствуют в production-HTML, карточках, связанных материалах и sitemap; прямой URL возвращает 404. Если публикаций ещё нет, список пуст, закрыт от индексации и не добавлен в sitemap.
- Не переносите готовую preview-сборку в production через Promote/`--prebuilt`: она содержит превью. Для публикации нужна новая production-сборка.

## Как опубликовать после проверки

1. В файле одобренного материала смените `status` на `"published"` и добавьте реальную дату `publishedAt: "YYYY-MM-DD"`. `updatedAt` не должна быть раньше даты публикации. Все три перевода публикуются вместе.
2. Выполните `npm run lint` и production-сборку без `ARTICLES_PREVIEW`. Из-за статической генерации изменение файла требует новой сборки.
3. Проверьте результат. Деплой на рабочий домен выполняйте только после отдельной команды владельца.
4. После деплоя проверьте новые страницы и `https://lumacleanrs.com/sitemap.xml`. Статья добавится автоматически на трёх языках; первая публикация также добавит три страницы списка. После публикации всех четырёх материалов первоначально ожидалось 33 URL в sitemap; после второй серии — 63 URL, если остальные страницы не менялись.

Не меняйте уже опубликованный slug без постоянного редиректа со старого адреса.

## Проверки

Из корня репозитория:

```powershell
node docs/articles/check-articles.cjs
node docs/articles/check-articles.cjs http://127.0.0.1:3100 preview
node docs/articles/check-articles.cjs http://127.0.0.1:3101 production
# Только после разрешённой публикации:
node docs/articles/check-articles.cjs https://lumacleanrs.com published
```

Скрипт проверяет разделение статусов, SEO опубликованного материала на временной модели в памяти, sitemap, HTML-текст, разметку, ссылки, якоря и обложки. Исходники и статусы он не меняет. Число 18 в скрипте — существующие главная и страницы услуг; его нужно обновить, если изменится эта часть структуры.

Отчёт о выполненных проверках: [verification.md](verification.md). Настройка поисковых кабинетов и действия после публикации: [indexing.md](indexing.md).
