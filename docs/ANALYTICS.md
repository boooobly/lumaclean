# Аналитика LumaClean

Состояние на 21 сентября 2026 года. GA4 подключена в production через `NEXT_PUBLIC_GA_MEASUREMENT_ID`. Preview и локальная разработка не загружают внешний скрипт. На рабочем домене загрузка начинается только после согласия посетителя; выбор доступен в «Настройках приватности».

## События

| Событие | Значение |
|---|---|
| `form_start` | Первое взаимодействие с формой за её текущий монтаж |
| `calculator_interaction` | Изменение калькулятора; ограничение частоты раз в 2 секунды |
| `generate_lead` | Сервер принял заявку: HTTP OK и `{ok:true}` |
| `lead_error` | Ошибка валидации, сети или сервера |
| `messenger_click` | Клик по контакту; не подтверждение заявки |
| `article_to_service` | Переход из статьи к услуге |

В кабинете GA4 `generate_lead` отмечено ключевым событием, без денежной ценности по умолчанию, с подсчётом один раз на событие. Enhanced Measurement отключено, просмотры страниц отправляются кодом. Имена, телефоны и текст заявок в аналитику не передаются. Страницы ограничены списком опубликованных URL, без query/hash. Заявки принимает Telegram по отдельной серверной конфигурации.

Каждая успешно провалидированная попытка доставки получает номер `LC-YYYYMMDD-XXXXXXXX`. Этот номер включён в сообщение менеджеру. Для заявок из калькулятора Telegram-уведомление также содержит выбранную услугу. Серверные логи содержат только номер заявки, язык, код услуги, разрешённые `entry_source`/`landing_page`, технический результат доставки и длительность. Имя, телефон, комментарий и расчёт в логи не записываются. GA4 подтверждает только событие обращения, а не заказ или выполненную уборку.

## Ручная воронка до выполненной уборки

[Таблица LumaClean — воронка заявок](https://docs.google.com/spreadsheets/d/1pLZTmJ5who0A72WGLM5B47ygSKNA1zClydby2okK1jU/edit) — закрытый рабочий журнал без имён и телефонов. Для заявки с сайта менеджер переносит из Telegram номер `LC-…`, время получения, услугу, источник и страницу входа. Время первого ответа, статус (`Новая → Ответили → Согласована → Выполнена` либо `Потеряна`) и фактическую выручку он заполняет по мере работы. При отказе полезно указать причину. Для обращений напрямую в мессенджер или по телефону без номера `LC-…` применяется внутренний код `M-ГГГГММДД-01`; неизвестный источник не следует приписывать поиску. Время записывается по Белграду, таблица настроена на `Europe/Belgrade`.

Сверху таблица считает обращения, согласованные и выполненные заказы, долю выполненных, заказы из органического поиска и долю первых ответов не позднее 5 минут среди заявок с заполненным временем ответа. Счётчик приоритетных выполненных заказов включает поддерживающую и генеральную уборку. Счётчики обновляются только после ручного внесения строк; `messenger_click` и `generate_lead` не считаются выполненными заказами.

Зарегистрированы параметры уровня события: `entry_source`, `landing_page`, `locale`, `service`, `channel`. 29 сентября добавлен `error_type` («Тип ошибки заявки»): только `validation`, `server`, `network`, без текста ошибки и персональных данных; регистрация не дополняет прошлые отчёты задним числом. Для исследования заявок используйте первые четыре и фильтр `event_name=generate_lead`. Для кликов в мессенджеры — `channel` и `messenger_click`, для диагностики — `lead_error` и `error_type`. Источник — грубая категория по браузерному referrer, не точная UTM-атрибуция. Полный referrer не отправляется, поэтому стандартные отчёты привлечения GA могут показывать direct. Не приписывайте неизвестным входам источник поиска.

## Проверки

`?analytics_debug=1` помечает события `debug_mode=true` и `traffic_type=internal`. В GA4 активен Internal Traffic с точным условием `traffic_type=internal`. Метку нужно сохранять в адресе каждой проверяемой страницы: после перехода на URL без неё тестовый статус не гарантирован. Обычные визиты сотрудников автоматически не исключаются. Фильтр не меняет уже собранные данные.

Для локальной проверки без настоящей доставки заявки: `node docs/articles/check-seo-events.cjs`. Скрипт проверяет whitelist полей, отсутствие персональных данных в серверных логах, безопасный номер заявки, ошибки, успешный ответ, параллельную повторную отправку и API с подменой внешних запросов. Настоящее получение менеджером заявки этот тест не подтверждает. В Realtime подтверждён тестовый просмотр страницы; реальные конверсии нужно проверять отдельно после первого обращения.

При смене домена обновите origin в аналитике, список разрешённых страниц и удаление cookie. При добавлении страниц вне услуг/статей добавьте их в разрешённый список. Не включайте Google Ads или дополнительные категории передачи данных без отдельной задачи.
